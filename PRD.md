# PRD: Платформа анализа рыночных ставок БВУ РК по залоговым кредитам МСБ

## 1. Обзор продукта

**Название:** Платформа конкурентного анализа ставок БВУ (рабочее название)
**Тип:** Внутренняя аналитическая веб-платформа
**Пользователи:** начальник управления, директор департамента
**Стиль интерфейса:** деловой, лаконичный, приоритет читаемости данных над визуальными эффектами

**Одно предложение:** Платформа автоматически собирает с сайтов банков второго уровня (БВУ) РК условия залогового кредитования малого бизнеса, сравнивает их между собой и показывает конкурентные преимущества/недостатки каждого банка относительно рынка.

## 2. Проблема

Сейчас нет единого места, где можно быстро увидеть, как условия по залоговым кредитам МСБ у разных банков РК соотносятся друг с другом. Сбор и сравнение данных вручную — трудозатратный процесс, который не даёт актуальной картины на постоянной основе и не масштабируется на все 20 БВУ.

## 3. Цель и задачи

**Цель:** дать руководству инструмент для быстрого и актуального конкурентного анализа рынка залоговых кредитов МСБ по всем БВУ РК.

**Задачи:**
- Автоматически собирать данные по ставкам и условиям кредитования МСБ с сайтов БВУ.
- Приводить данные разных банков к единому сопоставимому формату.
- Визуализировать сравнение банков между собой.
- Автоматически формулировать конкурентные преимущества/недостатки каждого банка относительно рынка.
- Давать возможность выгрузить результат отдельным отчётом.

## 4. Пользователи и роли

| Роль | Возможности |
|---|---|
| Начальник управления | Просмотр дашборда, фильтрация, выгрузка отчётов |
| Директор департамента | Просмотр дашборда, фильтрация, выгрузка отчётов, просмотр истории изменений ставок |
| Администратор/оператор данных | Управление списком банков и источников, верификация спарсенных данных, ручной запуск парсинга |

**Доступ:** отдельный логин/пароль для каждого пользователя (без SSO/AD).

## 5. Объём данных

### 5.1 Охват банков
Все действующие БВУ РК — на 2026 год их 20 по реестру АРРФР. Точный список нужно сверять с реестром АРРФР на момент разработки (https://www.gov.kz), т.к. состав банков периодически меняется.

### 5.2 Сегмент
Только залоговое кредитование малого бизнеса.
**Явно исключено:** онлайн-займы, беззалоговые продукты, потребительские кредиты, кредиты для крупного/среднего бизнеса.

### 5.3 Источники
Официальные сайты банков, разделы "Кредиты для бизнеса" / "МСБ". Готового списка ссылок нет — его сбор и поддержание входит в объём проекта (см. Функциональный блок F5).

### 5.4 Параметры для сравнения по каждому банку
- Процентная ставка (диапазон мин.–макс. либо фиксированная)
- Сумма кредита (мин.–макс.)
- Срок кредитования
- Требования к залогу (вид залога, LTV/соотношение кредит-залог)
- Требования к заёмщику (стаж бизнеса, оборот и т.п., если указаны)
- Комиссии и доп. платежи
- Способ погашения (аннуитет/дифференцированный)
- Дата последнего обновления данных

## 6. Функциональные требования

### F1 — Сбор данных (парсинг)
- Автоматический плановый парсинг сайтов банков — 1 раз в месяц.
- Автоматический внеплановый парсинг при изменении базовой ставки Национального Банка РК (платформа отслеживает значение ставки НБ РК, например через официальную страницу НБ РК, и при изменении запускает полный парсинг всех банков).
- Нормализация данных в единую структуру.
- Логирование результатов парсинга по каждому банку (успех/ошибка, причина ошибки).
- Ручная проверка/корректировка данных оператором перед публикацией на дашборде.

### F2 — Историческая динамика
- Хранение и отображение динамики ставок за последний год и за текущий год, с графиком по каждому банку.
- Для данных за прошлый год (до запуска платформы): попытка восстановления через архивные снимки страниц банков в Wayback Machine (web.archive.org).
  - Ограничение: покрытие Wayback Machine по сайтам банков РК не гарантировано и может быть неполным/неравномерным — по части банков история может отсутствовать или быть частичной. Закладывается как ожидаемый риск, не гарантированный результат.
- Дополнительно — история базовой ставки НБ РК (публикуется открыто и полно) как общий ориентир динамики рынка.
- С момента запуска платформы история ведётся полностью и без пробелов за счёт планового парсинга (F1).

### F3 — Модуль анализа
- Расчёт средней/медианной рыночной ставки по сегменту.
- Позиционирование каждого банка относительно рынка (выше/ниже среднего).
- Автоматическое формирование конкурентных преимуществ/недостатков банка (например: «ставка ниже рынка на X%», «требует более высокий LTV, чем в среднем по рынку»).

### F4 — Дашборд
- Сравнительная таблица по всем банкам с сортировкой и фильтрацией (ставка, сумма, срок и т.д.).
- Графики сравнения ставок между банками.
- Карточка банка: детальные условия + список преимуществ/недостатков.
- Индикатор актуальности данных (дата последнего обновления по каждому банку); визуальная пометка "устарело", если данные не обновлялись дольше месяца.

### F5 — Администрирование
- Управление списком отслеживаемых банков и ссылок на их страницы условий (включая первоначальный сбор этого списка — готового нет).
- Ручной запуск парсинга вне расписания.
- Просмотр логов парсинга и уведомления администратору о сбоях (изменилась структура сайта, сайт недоступен и т.д.).

### F6 — Отчёты
- Выгрузка сравнительного отчёта в PDF и/или Excel.
- Выбор банков и параметров для включения в отчёт перед выгрузкой.

## 7. Нефункциональные требования

- **Доступность данных:** обновление не реже 1 раза в месяц + обязательное внеплановое обновление при изменении базовой ставки НБ РК.
- **Устойчивость парсинга:** изменение структуры сайта банка не должно приводить к тихому отказу — должно быть уведомление администратору.
- **Юридический аспект:** сбор публично доступной информации (тарифов) с сайтов банков обычно не нарушает законодательство, но нужно уважать `robots.txt` и не создавать избыточную нагрузку на серверы банков разумной частотой запросов. Это не юридическая консультация — при необходимости уточнить с юр. службой.
- **Хранение истории:** каждое значение ставки сохраняется с датой фиксации.
- **Безопасность:** доступ только по логину/паролю, платформа не публичная.

## 8. Технологический стек (предложение)

- **Backend:** Python (FastAPI)
- **Парсинг:** BeautifulSoup / Playwright (для сайтов с JS-рендерингом)
- **Планировщик:** Cron / APScheduler
- **База данных:** PostgreSQL (хранение исторических данных)
- **Frontend:** React + Recharts (графики)
- **Отчёты:** openpyxl (Excel), WeasyPrint (PDF)
- **Хостинг:** внутренний сервер компании либо облако с ограниченным доступом — по требованиям ИБ

## 9. Этапы реализации

| Этап | Содержание |
|---|---|
| MVP | Сбор и верификация списка ссылок на страницы условий по каждому БВУ; ручной/полуавтоматический сбор данных по 5–7 крупнейшим банкам; базовая сравнительная таблица |
| Этап 2 | Автоматический парсинг всех 20 БВУ (F1); расчёт рыночных показателей и преимуществ/недостатков (F3); попытка восстановления истории за прошлый год через Wayback Machine (F2) |
| Этап 3 | Полноценный дашборд с графиками динамики (F4); выгрузка отчётов (F6); триггер обновления по ставке НБ РК |
| Этап 4 | Роли/доступы, уведомления о сбоях парсинга (F5), доработки по обратной связи пользователей |

## 10. Критерии приёмки

- Данные по залоговым кредитам МСБ отображаются не менее чем по 90% отслеживаемых БВУ.
- Дашборд сортируется/фильтруется минимум по ставке, сумме и сроку кредита.
- По каждому банку — минимум 2 автоматически сформированных преимущества/недостатка относительно рынка.
- Отчёт выгружается в PDF и Excel без ручной доработки.
- Данные не старше порога актуальности (раздел 7), иначе — пометка "устарело".

## 11. Вне рамок проекта (Out of scope)

- Онлайн-займы и беззалоговые продукты.
- Кредитование крупного/среднего бизнеса.
- Публичный/внешний доступ к платформе.
- Интеграция с корпоративной SSO/AD (на текущем этапе).

## 12. Риски

- **Неполнота исторических данных за прошлый год** — зависит от покрытия Wayback Machine по сайтам конкретных банков, не полностью контролируется проектом.
- **Изменение структуры сайтов банков** может ломать парсеры — требует мониторинга и оперативной поддержки (см. F5).
- **Разнородность подачи условий** банками может усложнять нормализацию данных под единый формат.
